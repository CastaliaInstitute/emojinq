# Label-blind recognition evidence protocol

The recognition gate is a human observation protocol, not a score generated by
the font build. It exists to test the claim that every concrete Emojinq glyph
is recognizable without its label at toddler scale.

## One session

Use one child aged 12–47 months and one adult recorder. The runner shows each
selected object twice, once in ink and once in its familiar-color presentation
or declared ink fallback, at exactly 32 CSS pixels. The adult must not name the
object, gesture a clue, or offer choices. Record the child's words verbatim.

Expected labels appear only after every trial in the session is finished. At
that point the adult may approve a synonym that clearly identifies the same
object, documenting the rationale in Notes. Ambiguous, unrelated, or absent
answers are rejected. A rejected glyph requires redesign; unchanged rejected
artwork is not offered for another attempt.

## Divide work without overlap

The Assignment menu partitions the selected category into stable sets of 5,
10, or 25 candidates. Choose a numbered assigned set and use its generated
share link. A coordinator should give each observer a different link. Trial
order is still randomized, and labels remain hidden.

The default 10-object set produces 20 image trials. Across the current 1,142
candidates there are 115 global sets. Smaller sets are appropriate when a child
loses interest; never continue through fatigue simply to complete a batch.

Random selection remains available for exploratory sessions, but numbered sets
are the auditable choice for distributed completion. The exported JSON contains
candidate IDs and exact ink/color hashes, not an authority to change the
ledger.

## Validate and import

Keep every downloaded session JSON as raw evidence. Dry-run all new sessions
together so duplicate assignments are rejected before any write:

```sh
python scripts/import_pua_recognition_session.py sessions/*.json
```

After reviewing that summary, import deliberately:

```sh
python scripts/import_pua_recognition_session.py --write sessions/*.json
make recognition-ledger
make release-check
```

The importer rejects stale hashes, duplicate IDs, invalid ages, missing
verbatim guesses, missing protocol attestations, and attempts to overwrite an
already approved or rejected record. Rebuilding the ledger preserves evidence
only while both reviewed asset hashes remain unchanged. A changed drawing
returns that candidate to pending automatically.

## Release interpretation

`make check` verifies automated rendering, style, metadata, catalog, and font
invariants. `make release-check` additionally requires an approved, current,
label-blind observation for both presentations of every candidate. Until that
command passes, the public site is a review build rather than an evidence-backed
recognition release.
